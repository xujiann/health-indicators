# 发布与回滚

主分支每次变更均先执行生成物校验、数据校验、单元测试、浏览器测试和 2 秒首屏性能预算，通过后由 GitHub Pages 发布。

## 发布

1. 在拉取请求确认所有检查通过。
2. 合并到 `main`；`pages.yml` 自动部署。
3. 在 Pages 环境确认首页、城市分析页、数据包和工作簿返回 200。
4. 版本和变化分别记录在 `data/release.json` 与 `CHANGELOG.md`。

## 回滚

1. 打开 Actions 的 `Rollback GitHub Pages`。
2. 输入最后一个已验证的提交 SHA 或标签。
3. 工作流会检出该版本，重新执行全量测试，再部署相同静态产物。
4. 验证 Pages 环境并在变更记录中登记原因、目标 SHA 和恢复时间。

## 演练记录

2026-08-19 已完成静态产物回滚演练：使用当前提交的父提交作为 `ref` 构建，通过同一测试与打包命令验证后不执行生产部署；确认目标引用、测试门禁、产物清单和部署步骤均可复现。生产回滚必须由维护者手动触发，防止误覆盖。
