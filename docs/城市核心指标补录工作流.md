# 城市核心指标补录工作流

这套流程用于补齐 15 个副省级城市 2020—2025 年的 7 项核心经济、人口和财政指标。目标是让“发现缺口—核验原文—写入事实源—重建发布物—测试”形成可重复闭环，同时避免用推测值、二手网页或栏目首页代替正式数据。

## 1. 获取待办台账

执行：

```powershell
npm run build:data
```

生成的 `data/subprov-core-matrix-backlog.csv` 每行对应一个尚未覆盖的“城市 × 年份 × 指标”单元。城市代码、年度、指标键、对比口径和单位已经锁定；维护人员只需补充：

- `value`：官方原文中的数值，只填数字，不附单位；
- `source_url`：具体统计公报或财政公开材料的政府网站原文链接；
- `responsible`：发布部门；
- `source`、`doc_no`、`note`：可选，但建议填写来源标题、文号和必要的口径说明。

没有填写任何证据字段的空白待办行会被跳过；只填了一部分证据的行会被视为错误，防止半成品入库。

## 2. 只读预检

建议把已完成的行另存为一个 CSV，也可以直接使用完整台账。先运行：

```powershell
npm run import:subprov -- .\待补录.csv
```

预检会阻止：

- 不在清单内的城市、城市代码、年度和核心指标；
- 与标准对比口径或单位不一致的行；
- 空值、非数值和重复单元；
- 已经发布、可能造成覆盖写入的单元；
- 非 `gov.cn` 政府域名，或不是 HTTP(S) 的来源链接；
- 缺少发布部门的记录。

JSON 输入同样受支持，格式可以是行数组，也可以是 `{ "rows": [...] }`。

## 3. 写入事实源

预检通过并人工复核原文后执行：

```powershell
npm run import:subprov -- .\待补录.csv --write
```

命令会把记录合并到 `data/subprov-core-matrix-additions.json`。它不会修改已经发布的单元，也不会直接改写 `public-data.js`。

## 4. 重建与验收

```powershell
npm run build:data
npm test
```

构建会同步更新：

- `public-data.js` 和 `data/public-data-manifest.json`；
- `data/coverage-report.json`；
- `data/subprov-core-matrix-backlog.csv`；
- `docs/数据覆盖率报告.md`；
- `coverage.html`。

补录成功后，相应缺口应从台账和维护页消失，覆盖数应增加。提交前仍需打开来源原文抽查数值、年度、单位和口径。

## 5. 来源与口径边界

- 优先使用城市统计局、财政局或市政府发布的单条统计公报和决算公开材料。
- 栏目首页只能作为发现线索，不能作为补录证据；现有“公开来源索引（非单条原文）”记录也应逐步替换。
- 同名指标口径不一致时不要强行合并，应在 `note` 说明并先更新口径设计。
- 不得录入未确认公开的内部材料、截图推测值或无可追溯原文的数据。
