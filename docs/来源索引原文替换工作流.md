# 来源索引原文替换工作流

公开数据中的“来源索引”只指向政府网站栏目或门户入口，不是单条统计原文。本流程用于在不直接编辑大型基础数据文件的情况下，把已经核实的公报、报告或公开材料原文安全绑定到具体记录。

## 1. 获取待替换台账

执行：

```powershell
npm run build:data
```

生成的 `data/source-index-backlog.csv` 每行对应一条来源索引记录，已经预填：

- `record_key`：由地区代码、年度、指标口径、数据性质和地区层级组成的稳定唯一键；
- `region`、`year`、`compare_key`：人工核验上下文；
- `current_source_url`：当前栏目或门户入口。

维护人员需要填写：

- `source_url`：具体公报、报告、PDF 或公开材料的政府网站原文链接；
- `source`：原文标题；
- `responsible`：发布部门；
- `doc_no`、`note`：可选的文号和口径说明。

完全空白的替换字段会被跳过，部分填写的行会被拒绝。

## 2. 只读预检

```powershell
npm run import:provenance -- .\原文替换.csv
```

预检会阻止：

- 当前数据中不存在或已经不是来源索引的 `record_key`；
- 与当前地区、年度、指标或栏目入口不一致的台账行；
- 根域名、栏目首页、与当前入口相同的链接；
- 非 `gov.cn` 政府域名或非 HTTP(S) 链接；
- 缺少原文标题、发布部门的证据；
- 已经覆盖或在同一批次重复的记录。

也可以提供 JSON 数组或 `{ "rows": [...] }`。

## 3. 写入证据覆盖层

人工打开原文并核实数值、年度、单位和口径后执行：

```powershell
npm run import:provenance -- .\原文替换.csv --write
```

命令只写入 `data/source-provenance-overrides.json`。该文件以稳定记录键保存来源证据，不复制或覆盖业务数值，也不直接修改 `data/base-public-records.json`。

## 4. 重建与验收

```powershell
npm run build:data
npm test
```

构建时覆盖层会在“来源索引兜底”之前应用。成功替换后：

- 对应记录使用具体原文链接、标题、发布部门和文号；
- “公开来源索引（非单条原文）”标记自动移除；
- `data/source-index-backlog.csv` 和维护页中的待替换数量自动减少；
- 数据值、单位、口径和唯一键保持不变。

## 5. 边界

- 一条原文可以覆盖多条记录，但每条记录都必须单独出现在台账和覆盖层中。
- 原文内容与现有数值不一致时，不应只替换来源；应先按数据补录或更正规则处理数值。
- 不得使用搜索结果页、第三方转载、媒体报道、内部材料或无法公开访问的链接。
